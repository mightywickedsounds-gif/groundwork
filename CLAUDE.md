# Flowtown (repo: groundwork)

A browser traffic game, hosted on GitHub Pages from `main` (root): https://mightywickedsounds-gif.github.io/groundwork/. This is a standalone project. The repo is public: never mention or link the owner's other projects, and keep personal details out of files and commit messages. The old digging game lives untouched in `dig/` (its own `dig/CLAUDE.md`; only read it when working there).

- No build step. three.js 0.160 from jsDelivr via the import map in `index.html` (CSP meta there; add any new host).
- `net.js` (no three, runs in Node): `Net` = nodes/edges (quadratic curves `cx,cz`, `oneway` 0/1/-1, `ring` id, `kind`), `probe`/`realize`/`planRoad`/`addRoad` (plan first without changing anything; every crossing becomes a junction or the road is refused with a `.reason`; `crossesOthers` + `restore(snapshot)` undo anything that would leave a crossing without a junction; snap radius passed in from the zoom), `removeEdge`, `toggleSignal`, `cycleOneWay`, `makeRoundabout`/`roundaboutOnRoad`/`removeRoundabout` (radius from `ringFit`, max `RING_R`, min 8, stored per ring node as `rc` [x,z,R]; close spokes share an entrance; one-way arcs going toward decreasing angle). `rebuild()` makes lanes (right-hand traffic, right normal is (-dz, dx), x east, z south) trimmed by `trimOf(node)` and connectors per node with `conflicts`; keeps cars and their routes when lanes survive. `step(dt)`: IDM following, junction permission `canEnter` (room on the out-lane, conflicting connectors `busy`, signal state, ring priority + ring fill cap `ringOcc`, first-come-first-served `arrT`), give up after `GIVE_UP` s. Routing = Dijkstra on lanes with `cost` (live lane speed `spd`).
- `city.js` (no three): `BLOCK` grid, districts of `CHUNK` blocks unlocked centre-out (`order`, `nextDistrict`, `unlock`), `fillBlock` lots (down/mid/sub zones), parks/parking/yards, `sync()` demolishes what roads run through and attaches buildings to streets, `demand`/`release` trips by `rushCurve(hour)`, `wild()` woods on unbuilt land (looks only). Never add random draws to existing generation (it would move things in saved cities); hash/seed only.
- `draw.js`: `buildRoads` (`piece` = one stretch of road; two roads joined end to end are drawn as one smooth `elbow`, not a junction; asphalt strips, junction fans with curb returns `corner`, raised sidewalks, markings, stop/give-way lines, zebras, islands, street-light spots), `buildCity` (instanced buildings with the window shader `buildingMaterial`, gable roofs, roof units, lots, parked cars, trees), vehicles (`vehicleGeos`, `aLight` 1 head / 2 tail, per-instance `aBrake`), people, lamp and signal models. Night uses `U.uNight`.
- `game.js`: camera (`cam` target/dist/yaw/pitch), tools (`TOOLS`, `click`, `hoverUpdate`, `previewRoad`, `place`, chain pin `T.pts`, curve pending `T.pend`/`T.bend`, `snapR()` = tap radius from zoom; touch: one finger draws with Road/Curve, two fingers move), magic sparkles (`burst`), traffic view (`buildOverlay`/`paintOverlay`), jam markers, day/night `lighting(hour)` (night is moonlit blue, `dark` = 0.6 of `night`; `nightOn` menu switch; `clockRate` 3x from 21:30 to 5:00), gridlock meter (`simStep`), growth (`growInterval`), saving (`flowtown.save.v1`, every 10 s + pagehide), quality `flowtown.quality` (`QS`), sound (made in code). `window.FT` = test hooks.
- Tests: `node tests/sim.mjs`, `node tests/grow.mjs`, `node tests/build.mjs` (random building stress test: must report 0 crossings without a junction), `node tests/play.cjs [outdir]`. Run them after any traffic or tool change and report results honestly.

It's an original game in the traffic/city genre: don't copy any existing game's name, art, levels or look.

Screen style (owner): solid road-sign UI (round 2): green guide sign `#hud`, yellow warning sign `#jam`, asphalt dock `#bar` with yellow for the active tile, `.sign` panels (inset border line), Overpass font in `assets/fonts/`. The owner hates the see-through/glassy floating-text look (it reads as AI-made): no translucent panels, text shadows, glows or letter-spaced captions in the UI. Keep it minimal: short labels, no paragraphs on screen, no emoji. Look: semi-realistic aerial city (real lighting and shadows), simplified driving.

The owner isn't a programmer: explain changes in plain English and log each round in README.md under History.
